# 按事件留存调试图片

默认 `debug_save_images=False`，任何路径均不写采集图。用户开启调试时，`debug_image_policy=events`：

- 正常成功帧只记录元信息，不写 PNG。
- 配准失败、OCR 异常、边界补识别异常、完整气泡没有识别文字、稳定超时和其他采集异常触发诊断。
- 未知类型消息保留原图上下文、区域裁剪、消息 ID 和本地框；有确认坐标才记录全局区间。
- 对同一未知消息去重，允许由首次截断视图升级到完整视图；长未知消息部分视图的全局范围新增超过 8px 时保留后续片段，避免因始终没有完整视图而丢掉后段。普通截断消息不会仅因不完整就触发图片。

## 文件关联

`frames.jsonl` 记录全部帧，`alignments.jsonl` 记录坐标判定；事件图片从 `retained_frames.jsonl` 和 `diagnostics.jsonl` 关联，不能通过原始帧记录有没有 image 字段推断所有图片都缺失。

`diagnostics.jsonl` 每条包含原因、当前帧、参考帧、坐标资格及 images。图片角色有 current、reference、unknown_crop、temporal_sample；包含相对路径、SHA-256、字节数，未知裁剪另有原框和实际 crop_box。

参考图是上一确认帧的原始 ROI，只在发生事件时写出。内存只保留一张额度管理的原图，替换/结束时释放，不攒历史图。图片写入/额度失败记录 image_save_error，保留已写图片并停止；当前窗口不可读时只保留可取得的参考画面与元信息，不重新激活或截图其他窗口。

稳定超时保留最近最多 3 张灰度样本（按时间由早到晚）及相应媒体区域，以重现灰度变化/遮罩判定。这些图像有独立预算所有权，写完或异常退出都释放；诊断图不增加累计位移。

所有原图、参考、裁剪和时间样本共用调试存储额度。相同帧作为多个事件参考时复用文件。索引缓存和消息去重缓存均有上限，保存数量不等于采样帧数。

## 兼容与分析

事件采集标记为 live_event_debug / event_images。因没有完整连续图像，完整回放/重识别工具明确拒绝，避免误把稀疏图片当作连续采集。可按索引检查单个事件或图像对；媒体核查工具已支持事件原图和未知裁剪索引。

开发时若需要完整帧，显式使用 `--debug-save-images --debug-image-policy all`；旧 live_debug / debug_images 归档继续支持校验和完整回放，自建模拟窗口集成工具也显式使用此模式。

## 验证

覆盖正常零图片、未知区域像素准确、重复去重及完整视图升级、配准失败的参考对、超时灰度时间窗、配额失败、OCR 报错/空识别、普通模式禁存、事件索引核查和旧全帧回放。正常/异常结束后的受管图像额度均归零。

全部使用模拟/离线及 Qt 离屏测试，没有操作用户微信窗口。图片和测试输出不随公开仓库上传。

最终全量结果为 299 项通过、8 项私有输入跳过；不含私有数据的副本为 297 项通过、10 项跳过。额外覆盖长未知消息新增片段的保存，重复片段不重复写图。
