# 重复头像、连续动图与稀疏正文

本次日志在 −13648px 后稳定超时，原因为 `stationary_content_unconfirmed`，动态覆盖约 8.7%；没有触及面积上限。64 帧已经确认，末帧仅作为未确认诊断元数据保留。该次没有保存原始截图，因此不能重放实际时间序列。

旧检测在较小动态面积下只验证全局唯一模板；严格静态特征回退仅在超过 12% 时启用。重复头像缺乏全局唯一性、正文又少时，视口即使静止也可能被拒绝。

修复后：

- 只要变化有媒体区域支持，较小动态覆盖也可使用严格零位移静态特征验证；媒体外变化限制不放宽。
- 没有独特特征时，允许用 32×24 有纹理小块在同一位置比较连续样本。要求多个不显著重叠的小块、至少 48px 的空间跨度，以及原像素覆盖/误差校验。
- 固定位置比较须使用整个媒体区域之外的内容，而非仅排除变化像素；这可避免遮罩把移动正文藏起来。
- 该证明仅用于确认某个视口在时间上稳定，绝不参与跨屏位移估计。位移仍由独立的 MotionTracker 验证。
- 日志记录采用的静态验证方法及支持数；普通采集仍不保存图像。

受控复现将用户提供的静态布局保留，在内存中为四个动图区域生成变化。约 8.46% 的动态覆盖下，旧唯一模板检查失败，新流程找到 54 个零位移静态特征并通过。另有合成数据强制缺少独特头像特征，验证固定位置小块路径；移动正文、滚动头像页面、无静态内容均拒绝。

还用该布局构造明确的 201px 合成跨屏变化，分别通过时间稳定检测和跨屏配准，累计结果 −201px。这里的 201px 是受控输入，不是对原失败帧位移的推算。

用户截图不会随仓库发布。私有参考测试通过环境变量 `WELOG_REPEAT_GIF_SAMPLE` 指定本地图片；未提供时跳过，其他回归全部采用合成数据。没有操作微信窗口或修改原采集记录。

本次完整测试 280 项通过、2 项缺失旧私有样本跳过；无私有数据副本 276 项通过、6 项跳过。日志增加 `static_method`，可区分模板、静态特征和原位置小块证明。没有当时的连续采样，实际现场效果仍需用户重新采集验证。
